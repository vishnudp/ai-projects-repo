This is consistent with the direction of current evidence-informed policy work: AI is most useful when it accelerates evidence synthesis while keeping human judgment, transparency and oversight in the loop. OECD also highlights the current gap between AI adoption and actual impact measurement in government, which is exactly why our design should capture outcomes rather than just initiatives.

7. Ollama architecture

Don't call Ollama directly from every agent.

Create a single abstraction:

                    AGENTS
                      │
                      ▼
              MODEL ROUTER
                      │
            ┌─────────┴─────────┐
            ▼                   ▼
       Chat Model          Embedding Model
            │                   │
            ▼                   ▼
          Ollama              Ollama
ollama_client.py

Responsible for:

- connection
- timeout
- retries
- structured output
- model selection
- token/runtime metrics

Agents should never contain:

ollama.chat(...)

directly.

Instead:

result = llm.generate(
    prompt=prompt,
    schema=ClaimExtraction
)

This gives us centralized control.

9. Caching architecture

This is extremely important because local LLM inference can become the bottleneck.

We should cache at multiple levels.

                    REQUEST
                       │
                       ▼
                  CACHE CHECK
                       │
             ┌─────────┴─────────┐
             │                   │
           HIT                  MISS
             │                   │
             ▼                   ▼
          Return              Ollama
                                  │
                                  ▼
                               Result
                                  │
                                  ▼
                              Cache
                                  │
                                  ▼
                               Return

10. Cache keys

Never use generic keys like:

claim_result

Use content-based keys.

For example:

llm:claim:v1:<sha256(document_text)>

Embedding:

embedding:v1:<sha256(chunk_text)>

Relationship:

relationship:v1:<claim_a_hash>:<claim_b_hash>

Trend:

trend:v1:<month>:<topic_id>:<corpus_hash>

Report:

report:v1:<month>:<topic_id>:<analysis_version>

This means if nothing changed, we don't invoke Ollama again.

11. Cache invalidation

We should version prompts.

For example:

claim_extraction:v1
claim_extraction:v2

If we improve the prompt:

llm:claim:v2:<content_hash>

The old cache remains valid for reproducibility.

This is much better than deleting the entire Redis cache.

13. Deduplication strategy

We need at least three levels.

Level 1 — URL
normalized_url
Level 2 — Content hash
SHA256(cleaned_content)
Level 3 — Semantic duplicate

Two documents may have different URLs but identical information.

Example:

Government announcement
News article
Press release reproduction

Calculate embedding similarity.

similarity > 0.95

→ potential duplicate.

Then use metadata:

same date
same entities
same claims
same title similarity

to confirm.

14. Don't use the LLM for basic deduplication

This would be wasteful.

Use:

URL
  ↓
Hash
  ↓
Metadata
  ↓
Embedding similarity
  ↓
LLM only if ambiguous

That's our general architecture principle:

Deterministic → statistical → LLM

25. One additional capability I recommend

Since this is meant for senior policymakers, add an "Evidence vs Recommendation" separation.

FACT

ANALYSIS

"The investment appears associated with increased renewable capacity."

INFERENCE

"Infrastructure availability may have contributed to adoption."

"India could consider a similar mechanism."

"Consider evaluating a public-private model for..."

These must never be mixed.

I would make this a hard guardrail.

9. Caching strategy

        ↓

        ↓

content_hash + embedding_model
             ↓
          cache hit?

Key:

    model +
    prompt_version +
    input +
    temperature

Same request → cached result.

query + filters + embedding_model

5. app/core/metrics.py

from dataclasses import dataclass, field
from time import perf_counter
from typing import Dict




@dataclass
class RuntimeMetrics:
    counters: Dict[str, int] = field(default_factory=dict)
    timings_ms: Dict[str, float] = field(default_factory=dict)


    def increment(
        self,
        name: str,
        value: int = 1,
    ) -> None:
        self.counters[name] = (
            self.counters.get(name, 0) + value
        )


    def record_timing(
        self,
        name: str,
        started_at: float,
    ) -> float:
        elapsed_ms = round(
            (perf_counter() - started_at) * 1000,
            2,
        )


        self.timings_ms[name] = elapsed_ms


        return elapsed_ms


    def snapshot(self) -> dict:
        return {
            "counters": dict(self.counters),
            "timings_ms": dict(self.timings_ms),
        }




metrics = RuntimeMetrics()

    @staticmethod
    def make_key(*parts: Any) -> str:
        payload = json.dumps(
            parts,
            sort_keys=True,
            default=str,
        )


        return hashlib.sha256(
            payload.encode("utf-8")
        ).hexdigest()


    def get(self, key: str) -> Any | None:
        path = self.root / f"{key}.json"


        if not path.exists():
            return None


        try:
            return json.loads(
                path.read_text(
                    encoding="utf-8"
                )
            )
        except (
            OSError,
            json.JSONDecodeError,
        ):
            return None

        self,
        key: str,
        value: Any,
    ) -> None:
        path = self.root / f"{key}.json"
        temporary = path.with_suffix(".tmp")


        temporary.write_text(
            json.dumps(
                value,
                ensure_ascii=False,
                default=str,
            ),
            encoding="utf-8",
        )


        temporary.replace(path)

It means Python successfully found:

app/api/main.py

but inside that module, Uvicorn cannot find:

app = FastAPI(...)

So this is not an import-path problem now. Let's fix main.py cleanly.

1. Check app/api/main.py

Replace the entire file with:

from fastapi import FastAPI


from app.core.logging import configure_logging
from app.core.metrics import metrics
from app.core.progress import progress_state
from app.documents.repository import (
    database_health,
    initialize_database,
)
from app.llm.ollama_client import ollama_client




# ---------------------------------------------------------
# Logging
# ---------------------------------------------------------


configure_logging()




# ---------------------------------------------------------
# FastAPI application
# ---------------------------------------------------------


app = FastAPI(
    title="Global Policy Intelligence",
    description=(
        "AI-powered global policy intelligence and "
        "knowledge digest platform."
    ),
    version="0.1.0",
)




# ---------------------------------------------------------
# Startup
# ---------------------------------------------------------


@app.on_event("startup")
def startup() -> None:
    initialize_database()




# ---------------------------------------------------------
# Health
# ---------------------------------------------------------


@app.get("/health")
def health() -> dict:


    # Check Ollama
    try:
        models = ollama_client.list_models()
        ollama_status = "connected"


    except Exception as exc:
        models = []


        ollama_status = (
            f"error: {type(exc).__name__}"
        )


    # Check database
    try:
        database = database_health()


    except Exception as exc:
        database = {
            "status": f"error: {type(exc).__name__}"
        }


    return {
        "status": "ok",
        "database": database,
        "ollama": {
            "status": ollama_status,
            "models": models,
        },
        "progress": progress_state.snapshot(),
        "metrics": metrics.snapshot(),
    }




# ---------------------------------------------------------
# Root
# ---------------------------------------------------------


@app.get("/")
def root() -> dict:
    return {
        "application": "Global Policy Intelligence",
        "version": "0.1.0",
        "status": "running",
    }

3. Test the import before starting Uvicorn

This is the fastest way to isolate the problem.

From:

/home/vishnu/policy-intelligence

run:

python3 -c "from app.api.main import app; print(app)"

You should get something like:

<fastapi.applications.FastAPI object at 0x...>

If this works, the ASGI problem is solved.

4. Then start Uvicorn
uvicorn app.api.main:app --reload

You should now see:

INFO:     Uvicorn running on http://127.0.0.1:8000

and no ASGI app error.
